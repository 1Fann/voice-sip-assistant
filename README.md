当前版本 **1.4.6**。用于部署、管理 Voice SIP Agent 与 Shizuku 的原创 Root 工具，不是上游官方 App，也不是 SIP 服务器。

- 获取上游最新正式版 APK，校验来源、摘要和签名；安装或升级时保留数据。
- 准备并以 Root 模式启动官方 Shizuku；支持可选开机准备。
- 查看状态、启停手机通话网关、重连 SIP、打开配置；在高级修复中恢复系统默认电话。
- 针对已测试联发科 ROM 的 Shizuku UserService 启动异常，提供 Root 兼容入口；保留用户授权与调用身份检查。
- 识别配套 [Voice SIP 网关](https://github.com/1Fann/voice-sip-gateway) 定制签名；不会用官方升级覆盖定制网关。


## 本次更新 1.4.6

每约 1 秒检查已知网关进程是否退出，退出后经过当前通话、签名、授权和手停检查再恢复。直接查询 PID 和 Wi-Fi 地址，减少启动开销；兼容空闲权限服务复用及重启后的常驻待绑定请求。配合网关 custom.5 使用。检测间隔不代表业务一定在固定时间内恢复，实际就绪仍取决于当前权限、音频、SIP 和服务器状态。

检查与升级的总超时在获取锁前建立，内部限时查询不继承检查锁；检查本体结束后立即释放锁，避免已结束任务的计时子进程阻挡下一次恢复。实际检查期间仍持有单实例锁和共享通话恢复锁。

## 可靠性加固 1.4.2

健康检查增加独立的单实例监护父进程，检查工作进程异常退出后自动重建；两个助手共用的恢复锁改为非阻塞获取，争用时短暂等待后重试，避免永久卡在锁上。系统服务轻检和开机状态查询设有超时。运行脚本通过原子替换更新，避免刷新时截断正在执行的脚本。Asterisk 的开机及系统重建入口尊重手动停止，关闭开机开关可以结束等待。

保留既有通话保护、签名校验、检查间隔和唤醒开关；不会自动整机重启或绕过首次解锁。父进程自身或整个设备失效、无唤醒能力的深睡以及外部网络故障仍需独立监测，不能保证零中断。隔离回归覆盖锁争用、重复启动、工作进程被杀后的恢复及关闭退出；真实长时间息屏和有密码的重启仍需验收。

## 上次更新 1.4.1

已确认的故障是系统限制后台运行 / 小米自启动关闭，以及状态检查仅看到旧注册状态。不是单纯检查间隔过长。

首次打开助手时显示“后台运行准备”。点击“检查 / 允许后台运行”并明确确认后，助手仅为自己及受信任的配套网关解除后台限制、加入电池优化白名单，并在可识别的小米系统允许自启动。电话、麦克风、通知及 Shizuku 权限仍需用户自行允许。遇到不支持的系统设置时说明具体失败项，不再统一提示 Root 失败。

自动检查开启时，每约 1 秒轻量检查已知进程是否退出，每 10 秒检查前台服务；完整检查仍按用户配置的 1–1440 分钟执行。授权后台设置后，检查任务可修复被重新施加的后台限制。Asterisk 与网关的恢复仍分属各自助手，共用恢复锁；通话中或无法确认通话状态时不重启，尊重应用内手动停止。清理最近任务无需加锁，但被杀进程恢复期间仍可能暂时无法接听，不承诺零中断。

专用唤醒锁继续由 Asterisk 的原有开关控制。开启时，Root 检查任务持有可续期、到期自动释放的唤醒锁，防止界面被清理后检查立即休眠；关闭时释放。DDNS 的独立守护和唤醒选项保持原状。

## 检查与恢复

可独立开启、关闭，间隔1–1440分钟（默认5），支持立即检查和上次结果。Root 检查任务独立于界面，清理后台后仍能检查；开机应用数据可用后恢复。未设置锁屏密码、PIN 或图案时通常无需手动滑开屏幕；有凭据时持续等待首次解锁，不再限制为约 15 分钟。通话中或无法确认通话状态时跳过恢复，Wi-Fi 未就绪时等待。关闭检查不会停止现有服务。深度休眠可能延后检查；清理至下次检查之间可能短暂不可用。

本助手只恢复 Shizuku、网关权限连接、音频就绪和 SIP 注册。Asterisk 由 [Asterisk 助手](https://github.com/1Fann/asterisk-assistant) 独立恢复；本助手只读检查服务器依赖。手机通话网关被手动停用时不拉起，恢复保留本机静音设置。严重权限故障可能重启 Shizuku 并打开网关页面，其他 Shizuku 客户端可能短暂断开。

开机入口防止重复启动；首次准备 Shizuku 失败仍启动检查，后续按配置重试。详见[开机恢复与实测](BOOT-RECOVERY.md)。

## 使用

Android12+、ARM64、Root；自动识别 Root 管理器的 BusyBox，无需软链接。安装后允许通知并授予 Root，再部署依赖，在网关内自行授权 Shizuku、填写 SIP 账号。账号不由助手保存。一键部署默认下载本项目的整合网关；保留同签名已有配置。

手机通话网关是双向蜂窝与 SIP 桥接的总开关。启用后将手机来电送到服务器，并允许 Groundwire 等 SIP 客户端通过手机 SIM 呼出；保留系统电话界面。停用后这两条通话链路停止，但独立 Asterisk 的回声测试仍可能正常。恢复默认电话仅用于高级修复。首次部署不再额外强制关闭本机通话静音，升级和启用均保留用户设置。开机准备与自动恢复开关独立；卸载前均应关闭。Root 文件位于 `/data/adb/voice-sip-assistant`。更新助手后自动刷新运行代码校验值；若系统拦截更新广播，打开助手即可重新检查。

## 自行构建与签名

Windows、JDK21、Android SDK35、Build Tools36.0.0：

```powershell
./build.ps1 -SdkRoot C:/Android/Sdk -JavaHome C:/Java/jdk-21
```

普通构建先核对现有签名与 App 信任指纹，失配立即停止。仅用于编译验证的临时 CI 构建需显式添加 `-DevelopmentSigning`；其 APK 不能用于覆盖升级正式安装。

构建脚本在本机 `private/` 生成签名文件。公开发布 APK 使用维护者的既有签名，可覆盖升级已安装版本；CI 使用临时签名，只验证构建。自行签名需要同步修改代码中的证书指纹：Asterisk 的 `RootBridge.CERT`；Voice SIP 助手的 `Root.DUALSIM_CERT`（其自身及配套网关信任指纹）。不同签名不能直接覆盖安装。私钥、密码和手机配置不在仓库中。

## 1.4.3 本地恢复速度改进（2026-10-31）

首次检测工作进程退出立即重建，连续快速退出才逐步退避。每秒仅使用缓存 PID 做存活检测，网关或 Asterisk 引擎退出会立即请求原有安全检查；前台服务检查仍每 10 秒执行。网络和依赖暂未就绪时，前 6 次在 3 秒后复查，随后降低频率。开机等待已解密存储和网络改为每秒检查。升级交接先等待正在执行的恢复检查结束，再更换监护进程。

这些时间是检测触发和隔离测试阈值，不等于通话全链路恢复时间；通话状态未知或忙碌、手动停用、签名验证和首次凭据解锁要求保持原有规则。
## 1.4.4 本机 MTK 连接恢复优化（2026-10-31）

已启用 MTK 兼容且网关明确进入授权后的绑定状态时，立即处理当前请求，减少重复启动和等待。兼容进程只使用当前进程、当前 APK 对应的新请求；签名、通话状态、手动停用和权限检查仍保留。连接成功后先等待正常 SIP 注册，不重复打断已经恢复的连接。

进程存活轻检测保持每秒一次；完整检查、3 秒暂态重试和 10 秒前台检查的时间间隔保持不变。检测速度不等于完整通话链路就绪时间。

## 1.4.5 常驻权限服务兼容（2026-10-31）

允许已签名网关使用 Shizuku 的正常常驻或非常驻请求模式。常驻服务的待处理授权请求可以早于当前网关进程，但必须属于当前 Shizuku 服务进程；非常驻请求同时受当前网关进程启动时间限制。最新请求、双方进程身份、APK/版本、权限和通话状态仍逐项校验；检测仍为每秒一次。本版助手本身不修改网关的常驻设置。

## 1.4.6 热恢复查询（2026-10-31）

恢复前的 PID 缺失判断改为直接发送信号 0；仅 ESRCH 且 `/proc` 证明进程缺失才允许快启，权限错误或 PID 复用继续拒绝。Wi-Fi IPv4 检查直接读取当前 `wlan0` 地址，每次启动前重新检查，减少重复命令进程开销。完整通话检查、两次授权/签名校验、手动停止保护及 1.4.5 的开机 token 规则保持不变。界面同步显示约 1 秒进程检测与每 10 秒前台检查；真实业务恢复需完成当前音频与 SIP 检查，不能由检测间隔推算。
本地构建同时加入限定的提前启动：只有监护确认原网关进程退出，且授权、签名、手动开关及实时通话检查全部通过时，才先请求前台服务。完整服务器、SIP 和后台权限检查继续执行；最终就绪条件不放宽。启动与检查可以重叠，不以启动成功代替电话恢复成功。
